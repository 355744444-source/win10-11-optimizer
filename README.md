# Windows 10 / 11 优化工具

一套**可回滚、可验收、可批量复现**的 Windows 客户端优化方案：一份判断口径 + 一个执行引擎 + 一个图形界面。

不做「削减功能」，只做「减少无效占用」。每一处改动都留下 JSON 变更清单，一条命令按逆序还原。

---

## 它解决什么问题

网上流传的优化清单最大的问题不是不够全，而是三件事没人交代：**改了会有什么风险**、**出事怎么退回去**、**怎么判断到底有没有用**。

这个项目把这三件事补齐：

- **风险分层**：L1 零风险 / L2 低风险 / L3 需评估，默认只下发 L1
- **可回滚**：每次应用生成 `%ProgramData%\WinOpt\manifest-*.json`，记录旧值与键是否原本存在
- **可验收**：给出开机耗时、空闲 CPU、启动影响项等量化门槛，改善 < 20% 判本轮无效

## 快速开始

### 图形界面（推荐）

下载 `Releases` 中的 `Windows优化工具_v1.1.exe`，双击运行：

1. 先点 **采集基线** —— 只读，生成当前状态报告
2. 再点 **演练 L1** —— 只打印将要改什么，不写入
3. 确认无误后点 **应用 L1** —— 需要写 HKLM 时会提示提权
4. 30 天后复测，对比验收指标；不满意点 **回滚最近一次变更**

### 命令行

```powershell
# 只读基线采集（默认模式，不改任何东西）
.\Optimize-WinClient.ps1 -Level Report

# 预览 L1 将要改动什么（不写入）
.\Optimize-WinClient.ps1 -Level L1 -Role Office

# 应用 L1
.\Optimize-WinClient.ps1 -Level L1 -Role Office -Apply

# 应用 L1 + L2（台式机 + 全 SSD 才会执行 L2 项）
.\Optimize-WinClient.ps1 -Level L2 -Role Dev -Apply

# 回滚最近一次变更
.\Optimize-WinClient.ps1 -Rollback
```

**没有 `-Apply` 一律视为演练**，任何写入路径都不会执行。这是硬编码的安全闸门，不是文档约定。

## 三档分层

| 档位 | 内容 | 边界 |
|---|---|---|
| **L1 零风险** | 关后台应用、关 Win11 小组件/搜索亮点/开始推荐、禁传递优化 P2P 上传、恢复经典右键、低配机关动画 | 全部用户态单值策略，任何人照做不会搞坏 |
| **L2 低风险** | 台式机切高性能电源、全 SSD 禁 SysMain、`DISM /StartComponentCleanup`（不加 `/ResetBase`） | 需管理员，逐项留痕 |
| **L3 需评估** | 关休眠/快速启动（BitLocker 恢复密钥风险）、关 VBS/HVCI（安全策略变更，须签字） | 单机决策，不做批量 |

### 四类机型差异

| 机型 | 关键约束 |
|---|---|
| **办公机** | 兼顾组策略与 Defender 合规，只走 L1 |
| **开发机** | 不得关 Hyper-V / 虚拟机平台 / 内核隔离 —— 会毁 WSL2、Docker、模拟器 |
| **设计机** | 不做激进服务与网络裁剪，关注 GPU 调度与色彩管理 |
| **笔记本** | **禁止**切高性能电源档 |

## 安全边界

以下配置**脚本永不修改**，只存在于文档的人工执行清单里。这是刻意的设计取舍，不是遗漏：

- Windows Defender / 实时防护
- Windows Update 通道
- VBS / HVCI / 内核隔离
- BitLocker
- 页面文件
- Windows Search 服务

**7 条红线**（任何机型都不进默认包）：关 Defender、关 Windows Update、删 WinSys/强删系统组件、禁用页面文件、关 Windows Search 服务、第三方"优化大师"类工具、把关 VBS 当批量默认。

## 目录结构

```
.
├── src/
│   ├── Optimize-WinClient.ps1          # 核心引擎：动作清单、执行、回滚（唯一真源）
│   ├── winopt_gui.py                   # 图形外壳：仅做参数编排与日志渲染
│   └── icon.ico
├── docs/
│   └── Windows10-11优化统一口径.md      # 结论 → 依据 → 下一步，含验收指标与分歧裁决
├── tools/
│   └── build-exe.ps1                   # 一键打包单文件 EXE
└── dist/                               # 构建产物（不纳入版本控制，走 Releases）
```

**架构上只有一层智能**：`Optimize-WinClient.ps1` 里的动作清单是唯一真源，GUI 与 EXE 都只是它的调用方。回滚逻辑（JSON 清单 + 逆序还原 + 整键删除）只实现一次，避免两套状态互相打架。

## 自行打包

```powershell
# 需要 Python 3.11+ 与 PyInstaller
pip install pyinstaller pillow
.\tools\build-exe.ps1
```

产物落在 `dist/`。注意 EXE 内嵌的是打包那一刻的脚本副本 —— **改了 `.ps1` 必须重新打包**，否则 EXE 仍执行旧逻辑。

## 已知限制

- **开机耗时事件（Event ID 100）**需要管理员权限，且系统需累计若干次启动后才有记录；采集不到时降级为提示，不报错
- **禁用 SysMain 的收益本就存在分歧**：SSD 上趋近 0，机械盘可能更慢，故 L2 仅在「全 SSD」时启用
- **关 VBS 的帧率收益**约 3%~8%，强依赖硬件；办公场景实测接近 0，不作为默认项
- 遥测类改动收益 < 1%，不计入性能项

# Windows 10 / Windows 11 优化统一口径

| 项目 | 内容 |
|---|---|
| 适用范围 | 办公机 / 开发机 / 设计机 / 个人机 四类终端 |

## 一、结论

### 1.1 总口径

> **优化只做「减少无效占用」，不做「削减功能」。每一处改动必须可回滚、可验收、可批量复现。凡触及安全边界（Defender、Windows Update、VBS/HVCI、BitLocker）的项，一律不进优化清单，走独立变更审批。**

三条派生规则：

- **默认只下发 L1**。L1 全部是用户态设置或单值策略，不依赖"手艺"，任何人照做都不会把机器搞坏。
- **L2 按机型开启，必须留痕**。逐项记录「改了什么、为什么改、怎么退」，脚本自动生成变更清单。
- **不拿安全换个位数性能**。具体红线见 1.5。

### 1.2 版本处置（优先级高于任何调优）

| 系统 | 支持状态 | 处置 |
|---|---|---|
| Win10 22H2 家庭版 / 专业版 | 常规支持已于 2025-10-14 结束；消费者 ESU 通道至 2026-10-13 | **停止新增入网**；存量机器限期升 Win11。必须保留的，先确认企业 ESU 覆盖 |
| Win10 企业版 / 教育版（ESU） | 最长至 2028-10-10 | 可继续使用，按本口径优化 |
| Win10 LTSC 2021 / 2019 / IoT 2021 | 2027-01 / 2029-01 / 2032-01 | 可继续使用，按本口径优化 |
| Win11 全版本 | 均在支持期内 | 常规优化 |

**理由**：一台已停止安全更新的终端，做再多性能调优都是在放大风险敞口；且 Win11 默认开启虚拟化安全（VBS/HVCI），性能基线本就与 Win10 不同，跨版本套用同一份调优脚本必然得出错误结论。

> **不确定项**：以上为公开政策口径。消费者 ESU 是否已在贵司批量许可范围内延续，需以授权凭证为准，本文不做推定。

### 1.3 动作分层

#### L1 零风险（默认执行，无需审批）

| 动作 | 手段 | 收益 | 说明 |
|---|---|---|---|
| 关闭后台应用 | HKCU 策略 | 内存 / CPU 中 | 不影响前台应用与系统组件 |
| 关闭 Win11 小组件、搜索亮点、开始菜单推荐 | HKCU / HKLM 策略 | CPU / 网络 中 | Win11 专属，纯减噪 |
| 关闭系统提示与"建议"内容推送 | HKCU | 网络 低 | 减少内容分发拉取 |
| 传递优化改为仅 HTTP（禁 P2P 上传） | HKLM 策略 | 出口带宽 高（批量场景） | 办公网最值得做的一项 |
| 恢复 Win11 经典右键菜单 | HKCU | 效率 中 | 纯体验项，可回滚 |
| 关闭视觉动画 | HKCU | 低配机体感明显，高配机为 0 | **仅 ≤8GB 内存或明确要求时执行**，高配机上别当性能项报 |

#### L2 低风险（需管理员，需留痕）

| 动作 | 前置条件 | 风险点 |
|---|---|---|
| 电源计划：台式机切「高性能」，笔记本保持「平衡」 | 无 | **笔记本切高性能会显著缩短续航，禁止** |
| 禁用 SysMain（Superfetch） | 全盘 SSD | 机械盘上会变慢；争议项，见 1.6 |
| 组件清理 `DISM /StartComponentCleanup` | C 盘可用 <15% | **不加 `/ResetBase`**，否则丧失更新卸载能力 |

#### L3 需评估（单机决策，不做批量）

| 动作 | 前置条件 | 风险 |
|---|---|---|
| 关闭休眠 / 快速启动 | 确认无 BitLocker，或恢复密钥已托管 | 可能触发 BitLocker 恢复密钥提示；双系统与部分驱动异常 |
| 关闭 VBS / 内存完整性 | 有本机同场景 A/B 实测数据 + 安全负责人签字 | 失去内核级代码完整性保护 |

### 1.4 四类机型适用矩阵

| 动作 | 办公 | 开发 | 设计 | 个人 |
|---|:--:|:--:|:--:|:--:|
| L1 全部 | ✅ | ✅ | ✅ | ✅ |
| 传递优化禁 P2P | ✅ | ✅ | ✅ | ⚠️ 可保留 |
| 关闭视觉动画 | 低配 ✅ | ⚠️ | ⚠️ | ✅ |
| 高性能电源（仅台式） | ✅ | ✅ | ✅ | ✅ |
| 禁 SysMain（仅 SSD） | ✅ | ✅ | ✅ | ✅ |
| 关闭休眠 | ⚠️ | ⚠️ | ⚠️ | ✅ |
| 关闭 VBS / HVCI | ❌ | ❌ | ❌ | ⚠️ |
| 关闭 Defender | ❌ | ❌ | ❌ | ❌ |

**机型附加约束**

- **开发机**：不得关闭 Hyper-V / 虚拟机平台 / 内核隔离（会破坏 WSL2、Docker、Android 模拟器）；不得关闭驱动签名强制；不得改动符号缓存与调试器相关服务。
- **设计机**：优先保证驱动与色彩配置稳定，不做激进的服务裁剪与网络裁剪；GPU 调度交给厂商控制面板，不用第三方工具改注册表。
- **办公机**：批量场景下，改动的**可回滚性**比收益更重要，L1 之外逐台决策成本过高，L2 应尽量走组策略/Intune 统一下发。
- **个人机**：允许更大胆，但个人机往往没有备份，L3 前务必建还原点。

### 1.5 红线（任何机型都不进默认包）

| # | 禁止项 | 一句话理由 |
|---|---|---|
| 1 | 关闭或阉割 Microsoft Defender 实时防护 | 收益不可测，风险是确定的 |
| 2 | 关闭 Windows Update / 长期挂起更新 | 与 1.2 直接矛盾 |
| 3 | 删除 WinSxS、强删系统组件、卸载"看似没用"的服务 | 更新失败与功能缺失，故障滞后且难归因 |
| 4 | 禁用页面文件 | 崩溃时无法生成 dump；Adobe 系、IIS、部分游戏直接报错，换来的只是几 GB 磁盘 |
| 5 | 关闭 Windows Search 服务 | 会同时打断开始菜单、Outlook、资源管理器搜索，正确做法是**收窄索引目录** |
| 6 | 第三方"优化大师 / 注册表清理"类工具 | 回滚求助的第一大来源 |
| 7 | 把关闭 VBS/HVCI 作为批量默认 | 这是安全策略变更，不是优化项 |

### 1.6 不确定项（明确标注，不假装确定）

| 流行说法 | 实际证据状况 | 本口径的处理 |
|---|---|---|
| 关 VBS 能提升游戏帧率 | 公开实测多在 3%~8%，强依赖 CPU/GPU 组合与引擎；办公场景基本为 0 | 仅个人机、且必须有本机同场景 A/B 数据，才允许单机执行 |
| 禁 SysMain 能提速 | 结论不一致。SSD 上收益趋近 0，机械盘上可能变慢 | 仅 SSD 机型执行，**不作为"提速项"对外宣传** |
| 关遥测能提升性能 | 实测普遍 <1%，主要价值是减少出网流量与合规面 | 归入网络/合规项，不列性能项 |
| 关快速启动能解决卡顿 | 对 SSD 冷启动影响约 1~2 秒，体感无差 | 仅在有驱动或双系统冲突证据时执行 |
| 关内存压缩能省内存 | 8GB 机型上大概率反而变差 | 不执行 |
| 清理注册表能提速 | 无可靠量化证据，收益不可测 | 不执行 |

## 二、依据

### 2.1 为什么按「收益 × 风险」分层，而不是给一张大清单

批量交付的失败成本，几乎全部来自**不可回滚的改动**，而不是"少做了几项"。经验上，前 5 项 L1 动作即可覆盖大部分可感知改善；越往后边际收益迅速递减、风险陡增。因此口径设计成：默认只下发 L1，L2 按机型开启，L3 单机审批——让没时间看推导的人，直接按机型选一行执行即可。

### 2.2 Win10 与 Win11 不能照搬的五个点

| 维度 | Win10 | Win11 | 对优化的影响 |
|---|---|---|---|
| VBS / HVCI | 多数机型默认关闭 | 新装默认开启 | Win11"变慢"的第一嫌疑是虚拟化安全，不是"系统垃圾多" |
| 待机模型 | 多为 S3 | 笔记本普遍 S0ix 现代待机 | 睡眠耗电要查驱动与固件，关服务无效 |
| 电源模型 | 以电源计划为主 | 以「电源模式」滑块为主，高性能计划被隐藏 | 直接拿 Win10 的 `powercfg` 脚本套 Win11 会静默失效 |
| 后台模型 | UWP 挂起策略较松 | 有"效率模式"，挂起更激进 | Win11 上"关后台应用"的边际收益低于 Win10 |
| 功能更新节奏 | 已停更 | 年度功能更新 + 月度累积 | 更新策略必须分开写，不能共用同一条组策略 |

### 2.3 四个关键判断的理由

**① 启动项是唯一「零风险高收益」项。** 它直接决定登录后前三分钟的资源竞争，且完全通过用户态开关控制、随时可恢复。所以它排第一，但必须**人工看"启动影响"列**——脚本只负责把清单和当前状态列出来，不替你决定关哪一项。

**② 页面文件坚决不动。** 禁用后系统无法在崩溃时落盘转储，且部分软件会直接报错。这是典型的"用确定性风险换几 GB 磁盘"。

**③ 索引要收窄、不要关。** Windows Search 同时支撑开始菜单、Outlook 与资源管理器搜索；空闲时它几乎不占资源，关服务的收益是错觉，代价是搜索能力全废。

**④ 关闭 VBS 是安全策略变更，不是优化项。** 它牺牲内核级代码完整性保护，换来个位数帧率。在企业终端上必须走变更审批；把它写进"优化脚本"是定性错误。

### 2.4 红线清单的来源

以上 7 条在各类"一键优化"教程中出现频率最高，也恰好是回滚求助最集中的项。共同特征是：**收益无法量化，故障现象滞后且难归因**（几周后某软件报错、某次更新后蓝屏），排障成本远高于收益。

## 三、下一步

### 3.1 四步落地（每步独立可验收）

| 步骤 | 内容 | 产出 | 单机耗时 |
|---|---|---|---|
| 0 基线 | 采集版本、开机耗时、启动项、磁盘余量、空闲占用 | 一份基线报告（脚本生成 md） | 约 1 分钟 |
| 1 应用 L1 | 按机型跑 L1 | 变更清单 JSON + 执行日志 | 约 1 分钟 |
| 2 按需 L2 | 台式机电源 / SSD 禁 SysMain / 组件清理 | 同上，逐项留痕 | 约 5 分钟 |
| 3 固化 | 验证通过后写成组策略或 Intune 配置 | 不再逐台手工 | 一次性 |

**Step 3 必须做。** 逐台手工优化的结果，一定会在半年内退化回原样。

### 3.2 验收指标（可直接抄进验收单）

| 指标 | 目标 | 取数方式 |
|---|---|---|
| 开机到桌面（SSD） | ≤ 25 秒 | 事件查看器 → 应用程序和服务日志 → Microsoft → Windows → Diagnostics-Performance，**事件 ID 100** 的 BootTime |
| 空闲 CPU（登录后 5 分钟均值） | ≤ 5% | 任务管理器 / `Get-Counter` |
| 空闲内存（16GB 机型） | ≤ 4.5 GB | 同上 |
| C 盘可用空间 | ≥ 15% | 资源管理器 |
| "启动影响 = 高"的条目 | 0 | 任务管理器 → 启动应用 |
| 优化后开机时间改善 | ≥ 20%，否则视为本轮无效 | 与 Step 0 基线对比 |

最后一条是硬门槛：改善不到 20%，说明瓶颈不在软件层（多半是磁盘或内存不足），继续调服务是白费功夫。

### 3.3 回滚

- L1 全部是单值策略写入，脚本运行前自动记录原值到 `%ProgramData%\WinOpt\`，`-Rollback` 一键还原。
- L2 的电源计划记录原方案 GUID、SysMain 记录原启动类型，同样纳入回滚清单。
- L3 的休眠关闭**无法完全回滚**（BitLocker 恢复提示可能已触发），故要求前置确认恢复密钥已托管。
- 变更前手工创建系统还原点；家庭版需先在「系统属性 → 系统保护」中开启保护。

### 3.4 脚本用法

```powershell
# 0. 只读基线采集（默认模式，不改任何东西）
.\Optimize-WinClient.ps1 -Level Report

# 1. 演练：不加 -Apply 一律只打印计划，不会写入
.\Optimize-WinClient.ps1 -Level L1 -Role Office

# 2. 应用 L1
.\Optimize-WinClient.ps1 -Level L1 -Role Office -Apply

# 3. 应用 L1 + L2（台式机 + 全 SSD）
.\Optimize-WinClient.ps1 -Level L2 -Role Dev -Apply

# 4. 回滚最近一次变更
.\Optimize-WinClient.ps1 -Rollback
```

两道安全闸门：**没有 `-Apply` 就不写**；`-Apply -WhatIf` 由 PowerShell 原生 `ShouldProcess` 逐条打印计划。变更前脚本自动记录原值并落盘 JSON 清单，`-Rollback` 逆序还原，本次新建的注册表键会被整键删除。

**脚本边界**（写在脚本头部，避免误期待）：永不修改 Defender、VBS/HVCI、Windows Update、BitLocker、页面文件、Windows Search 服务。这些只存在于本文的人工执行清单里。

### 3.5 图形界面版（给一线执行人）

`Windows优化工具_v1.1.exe`：单文件 GUI，约 10 MB，免安装、免 PowerShell 模块（Win10/11 自带 5.1 即可）。

界面两栏：**左栏**选机型（办公 / 开发 / 设计 / 个人，横向分段）与动作，**右栏**是实时日志（按 OK / WARN / ERROR / 跳过 分级着色，可整段复制）。

- 五个动作一键直达：采集基线 / 演练 L1 / 应用 L1 / 应用 L1 + L2 / 回滚，不用记参数。
- 需要写 HKLM 的动作先确认；普通用户下提示「以管理员身份重开」，不会静默丢项。
- 左栏底部常驻「最近变更 / 回滚可用」，不必翻目录判断能不能回滚。
- 支持明暗主题切换，标题栏跟随；界面按实测 DPI 逐项换算，不做位图拉伸。
- Win10 22H2 机器启动时直接给出停止支持提示条，不靠使用者自己想起来。

> 批量部署仍建议直接调 `Optimize-WinClient.ps1`（见 3.4）；GUI 更适合逐台处理与现场演示。
> **必须注意**：exe 内嵌的是打包那一刻的脚本副本。改了 ps1 必须重新打包，否则 exe 仍执行旧逻辑。

### 3.6 常见分歧的裁决口径

| 分歧 | 裁决 |
|---|---|
| "某教程说关掉这 30 项服务能快很多" | 服务裁剪的边际收益在 SSD + 16GB 的机型上接近 0，而故障率上升明确。不进默认包 |
| "客户机器老、只有 4GB 内存" | 优先加内存或换 SSD，优化收益上限很低。先做 L1 + 关动画，并把预期说明白 |
| "能不能一键全自动跑完" | 不能。启动项判定、L2 电源策略、L3 休眠都依赖具体机型与资产状态，全自动只会制造不可归因的故障 |
| "脚本跑完没变快" | 回 Step 0 基线，比对开机耗时。软件层已到平台的机型，继续调是负收益 |
